# Пункт 2 — транзакция пароля и Settings

Статус: VERIFIED. Backend и actual App runtime проверены; общий product finish остаётся задачей 16.

## Покрытие до изменения

Существовали password roundtrip в KAI и qTox SQLCipher checks. Не было отказов checkpoint/registry/rollback, cold recovery после отказа, транзакции Web dispatch и гонок actual Settings. Новые тесты дополняют существующие; прежние assertions сохранены.

## Воспроизведённые дефекты и ремонт

1. KAI возвращал ошибку внешнего checkpoint, сохраняя новый envelope в памяти. Откат теперь восстанавливает envelope под одним durability gate; неудачный durable rollback отравляет hook и блокирует последующие записи.
2. Registry mutation могла следовать отдельно от смены envelope. Новая операция проверяет запись и владеет registry lock до mutation; отказ реальной записи откатывает пароль. Cold discovery сверяет encrypted flag с валидным заголовком контейнера после неудачного отката.
3. Settings не передавал точный profileId и допускал поздний результат другого владельца. Снимок владельца, revision guards и синхронный single-flight ref защищают запрос/ответ/refresh; смена профиля очищает секреты и уведомления.
4. Web metadata rejection оставлял ложный encrypted badge. Candidate metadata теперь сериализуются и запечатываются до runtime mutation.
5. Реальный Web dispatch при отказе domain.json.new сохранял новый пароль, хотя возвращал ошибку. Password branch теперь владеет checkpoint и persist, откатывает пароль/metadata при отказе и возвращается без повторного generic persist.

## Новое исполнение

- Native: 8 новых тестов (4 KAI, 3 registry, 1 real Tox cold reopen). Проверены none → A → B → none, неверный current, checkpoint refusal, реальные .writing directory IO faults, rollback refusal/poison, disk bytes, cold recovery/retry, другой профиль и точный owner.
- Real Tox test холодно открывает identity/friend state после каждого шага; адрес, friend key и list совпадают. History/PQ byte canaries остаются точными; это сохранность байтов, не новый PQ protocol runtime proof.
- Actual RootApp/Settings: 14 assertions — mismatch без invoke, captured owner, double submit, disabled progress, masked fields, очистка секретов после успеха, reject/retry/remove, late A completion после переключения B, switch before RAF, отсутствие секретов в browser storage.
- Web native backend: 3 теста — metadata sealing refusal, explicit owner/none/A/B/none/wrong retry, actual dispatch+real durability с persist refusal, точными baseline bytes, cold domain/runtime restore и successful retry. HTTP/browser transport проверяется отдельно пунктом 12.
