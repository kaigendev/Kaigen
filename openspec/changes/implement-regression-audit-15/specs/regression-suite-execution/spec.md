# Spec Delta

## Purpose

Обеспечить воспроизводимый запуск автоматических регрессий Kaigen, полноту регистрации необходимых наборов и достоверное различение исполнения, пропусков и исторических результатов.

## ADDED Requirements

### Requirement: Полная регистрация и распространение ошибок

Система проверок SHALL регистрировать каждый тестовый entrypoint с исполняемым маршрутом либо явной причиной отдельного запуска. Регулярный агрегатор MUST возвращать неуспех при отказе любого включённого набора.

#### Scenario: Отказ готового набора
- **WHEN** набор звука уведомлений либо clipboard/pointer возвращает ошибку
- **THEN** регулярный агрегатор завершается с ненулевым кодом и не сообщает общий PASS

#### Scenario: Новый незарегистрированный тест
- **WHEN** добавлен тестовый entrypoint без регистрации
- **THEN** проверка полноты отклоняет каталог с именем отсутствующего файла

### Requirement: Достаточное поведенческое покрытие

Проверки MUST исполнять предусмотренные аудитом сценарии успеха, отказа, владения профилем, конкурентности и восстановления на соответствующем production-пути. Поддерживаемые платформенные сценарии SHALL подтверждаться фактическим исполнением на соответствующей платформе.

#### Scenario: Управляемый частичный отказ
- **WHEN** операция получает fault injection после частичного изменения
- **THEN** проверка подтверждает согласованное состояние памяти и диска, явную ошибку и корректный повтор либо восстановление

#### Scenario: Поздний ответ другого владельца
- **WHEN** ответ завершается после смены профиля, текста или поколения
- **THEN** проверка подтверждает, что новый владелец сохраняет корректное состояние

### Requirement: Честный учёт результатов

Каждый запуск MUST сохранять source/artifact/runner identities, команды и фактический результат. Discovered, executed и skipped SHALL учитываться отдельно; отсутствующий runtime MUST оставаться незавершённым результатом.

#### Scenario: Платформенная предпосылка отсутствует
- **WHEN** движок браузера либо MSI-среда недоступны
- **THEN** результат фиксирует blocker и следующий шаг, не заменяя runtime source-contract или driver self-test

#### Scenario: Историческая проверка переиспользуется
- **WHEN** используется ранее полученный PASS
- **THEN** запись сохраняет исходную identity и дату и не обозначает результат как новый запуск
