# Design

## Context

См. proposal.md. Исходное дерево чистое, HEAD 1060a86d6f0a997fb3db510baf98716ce6f24219. Орфография исполняется в worker; её причинная связь с симптомом не установлена.

В исходном клиенте была автоматическая синхронизация Windows-раскладки через frontend-события, native IPC и ActivateKeyboardLayout. Исправление очереди не устранило дефект. Валидные VM-сценарии подтвердили: после восстановления собственного окна из трея первый Ctrl+Shift не переключал RU в EN в пароле и composer; обычное восстановление возвращало переключение. Удаление layout bridge (DI31) и minimize-before-hide (DI32) отдельно оставляли FAIL. В DI33 штатное восстановление native WebView focus после top-level window focus устранило дефект: первый switch, реальный символ, WebView HKL и видимый OS indicator согласованы в unlock, composer и close-to-tray/restore сценариях.

Независимый дефект сообщений воспроизведён как устаревший диапазон виртуализации после возврата в кэшированный чат около нижнего края; новые сообщения получают место, но отсутствуют в DOM до прокрутки. Орфография выключена и включена в отдельных сценариях: дефект воспроизводился в обоих.

## Goals / Non-Goals

**Goals:** устранить подтверждённые гонки и задержки минимальным изменением общей codebase, добавить причинные регрессии и проверить desktop на disposable данных.

**Non-Goals:** язык интерфейса в настройках, предположение общей причины двух дефектов, изменение протокола Tox, managed dependencies, версии, release, production, реальных пользовательских данных и девяти постоянных test clients.

## Decisions

- Удалить автоматическую синхронизацию раскладки целиком: frontend-обработчики, native команду и ActivateKeyboardLayout. Выбор раскладки остаётся Windows и пользователю; клиент не восстанавливает ранее наблюдённый HKL.
- Keyboard regression охватывает composer и input[type=password] разблокировки профиля, без получения содержимого пароля.
- Обрабатывать один законченный клик трея (MouseButtonState::Up), показывать окно, использовать штатный window.set_focus() и только на Windows native WebView set_focus(). Layout setters и недоказанный AttachThreadInput fallback удалены. DI31→DI33 добавляет native WebView focus; сравнение сохраняет остальную product codebase и runtime. Предыдущие tray-прогоны с фиксированной координатой другой иконки исключены. Принимаемый сценарий получает прямоугольник собственной иконки через Shell_NotifyIconGetRect и подтверждает IsWindowVisible точного PID до/после каждого действия.
- Для новых incoming/outgoing фиксируются append, первый неполный snapshot, первый полный snapshot, DOM и painted geometry; clock не начинается только после готовности полного хвоста. Исправляется воспроизведённый переход диапазона/якоря с сохранением положения чтения. Native media route меняется только если отдельная причинная проверка связывает его с пустым местом, с независимой проверкой границы доступа.
- Runtime проверка сравнивает один disposable сценарий с орфографией on/off и отдельно текст-only/image-rich историю. Browser evidence дополняет, но не заменяет native Windows evidence.

## Risks / Trade-offs

- Удаление собственного layout bridge требует новой native проверки обеих полей, первого переключения после трея, реального символа и видимого системного индикатора. Успех сборки и прежние unit-тесты не подтверждают устранение симптома.
- Механизм eager IO не доказывает конкретный пользовательский симптом: причинные probes и native runtime результаты фиксируются отдельно.

## Migration Plan

После затронутых регрессий и checkpoint войти в Windows finish, собрать artifact только из изменённых product inputs, обновить программную часть exact local portable с сохранением protected roots и явным перезапуском. Затем выполнить обязательный local Web Lab маршрут отдельным этапом. Новые профили для проверок disposable; commit и публикация не выполняются.
