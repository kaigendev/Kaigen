# Design

## Context

См. proposal.md. `sendOnEnter` в App начинается с true и затем восстанавливает сохранённый boolean. WebRoot имеет ограниченную карточку внутри обрезающего viewport. App вызывает меню через contextmenu, macOS Ctrl-click и клавиатуру; touch удержание отсутствует. Защищённая pending запись принимается до асинхронного согласования PQ; active notice позднее добавляется в конец. Простая перестановка Vec не сохраняет порядок: durable store добавляет новый ID в chunks. Windows reveal передаёт canonical path непосредственно в команду Explorer.

## Goals / Non-Goals

**Goals:** сохранить реальные гарантии PQ и согласовать in-memory/durable порядок; исправить tablet ввод и доступность через общую оболочку; сохранить существующие menu actions, paths и настройки; связать полный регрессионный контур с immutable candidate.

**Non-Goals:** новый протокол PQ, изменение обычной offline/qTox доставки, новые mobile targets, обновление managed компонентов, изменение раскладки интерфейса вне формы и production Web/site deployment.

## Decisions

1. После genuine Active вставлять active notice перед earliest ожидающим protected ID через bounded durable insert-before operation. Сохранить prefix chunks и атомарно опубликовать suffix generation/revision. Дубли и failure/retry контролировать по ID; required notice persistence предшествует payload release. Предварительная фиктивная active карточка и перестановка только Vec отвергнуты: первая ложно подтверждает защиту, вторая не переживает чтение с диска.
2. Tablet default вычислять лениво из Web/native и browser device признаков. iPad mobile/desktop UA и Android tablet учитывать; Windows/Linux touch компьютер не менять. Сохранённый boolean и существующий Enter/Shift+Enter контракт выше default.
3. Web gate получает одну ограниченную viewport область вертикального скролла; card следует естественной высоте. Это устраняет clipping без второй вложенной scroll области и учитывает dynamic viewport.
4. Touch helper использует неподвижное удержание и существующие context routes. Не запрещать исходный pointerdown/scroll; отменять по движению, scroll, multitouch/cancel и lifecycle. После открытия подавлять только click данного gesture. Исключить editable/menu elements; сохранить right click/keyboard и menu coordinator.
5. Reveal проверяет canonical containment существующего downloads файла. Windows использует ограниченный native FFI `SHParseDisplayName` и `SHOpenFolderAndSelectItems` с точным item PIDL, UTF-16 и преобразованием verbatim Disk/UNC prefix только после security validation. COM init/uninit и освобождение PIDL сбалансированы; ошибка возвращается явно. Shell вызов выполняется через spawn_blocking, без изменения dependencies. Фактическая папка и selected item проверяются native, включая Unicode/пробелы; ошибку не маскировать fallback папкой.
6. Один writer на файл: PQ worker владеет Rust history/reveal; Web worker WebRoot/CSS/default helper и dedicated runtime fixture; координатор App/touch integration, версии, OpenSpec и release. Полный scope проверки включает предыдущие локальные изменения от последнего опубликованного release, включая обычную MSI upgrade/Finish acceptance.
7. Desktop↔Web harness принимает существующий hash-bound verification revision READY и завершает полный успешный сценарий отдельной штатной restore-веткой. До VM activation владелец независимо подтверждает SHA immutable inputs; success публикуется последним, после реальных scenario/history/UI receipts и остановки собственных процессов. Частичный UI run не закрывает full gate. Изменение runner не требует повторной упаковки приложения при неизменных shipped inputs; финальный source ZIP включает актуальный runner, а receipts сохраняют фактические built-from и runner identities.
8. Обычная per-user MSI проверка читает регистрацию через MsiGetProductInfoExW с actual current-token SID и unmanaged context2. ERROR_UNKNOWN_PRODUCT означает отсутствие; только advertised1/installed5 приняты, остальные ошибки и значения останавливают run. Related enumeration сохраняет same-thread/duplicate/bounds checks и фильтрует каждый ProductCode тем же scoped API. Для component clients selected SID должен совпасть с current token: MsiEnumClientsExW получает документированный NULL=current user и context2, а возвращённые SID/context строго сверяются с selected SID/context2. Фактический same-user probe подтвердил explicit SID error87 и NULL 316×NO_MORE_ITEMS до установки; это не installed-client acceptance. Observer загружается до первого Prepare state query. Живая install/Finish проверка требует actual console/Explorer выбранного disposable пользователя; host API controls её не заменяют.
9. Windows Edge pipe launch добавляет штатный `--edge-skip-compat-layer-relaunch`: точный установленный Edge без него завершался до CDP, с ним ответил и штатно закрылся. Child handle сохраняется сразу после spawn, включая ошибку подключения; bounded cleanup сохраняет исходную причину. После принятой owner activation полный неуспешный run публикует собственный abort перед finished. Локальные profiles удаляются только после подтверждённых process exits и доказанного prepared/no-workspace состояния либо уничтожения созданного workspace; null URL сам по себе недостаточен. Эти runner правки не ослабляют сценарии, историю или UI assertions.
10. Expanded UI runner использует фактический contenteditable composer и DOM Range offsets общего richTextEditor вместо прежнего textarea/value контракта. Сохранены реальные CDP input, text readback и исходные assertions, группы и deadlines. Ошибки formatting получают только фиксированный код этапа/invariant, включённый в ограниченный whitelist: исходный error повторно выбрасывается, текст сообщения, история и пути в receipt не добавляются. Выбор точки выделения использует видимый ненулевой hit-tested Range rect. Settings route сверяется с текущим avatar opener, Web-набором вкладок и фактической отменой подтверждения удаления; поддерживаемый малый viewport проверяется строгой геометрией и одинаковым smallViewportSupportedVerified у producer и consumers. Правка runner сама по себе не подтверждает product/runtime PASS; новый полный run сохраняет отдельную identity.
11. При запрете process-event CIM subscription выбранному обычному пользователю External WatchWorker выполняет только наблюдение в session0 существующего High controller. Отдельный SID явно задаётся локальным ExternalObserverUserSid и связывается с watch metadata, ready/heartbeat/stop/done stamps и lease; actual High/admin/token identity проверяется до подписки. MSI, UI, подготовка metadata и positive controls остаются в выбранной Medium console. Подписка не фильтрует запуски Kaigen по пользователю. Source/state hashes, свежая возрастающая heartbeat и финальный drain сохраняются; новый runner получает новый disposable state epoch, прежняя state не переименовывается и не перепривязывается. Учётные записи и политики Windows не меняются; персональных SID в canonical source нет.

## Risks / Trade-offs

- Durable insertion, queued snapshots и concurrent send: проверить порядок, revisions, cold read, failure/retry и стабильность IDs; не ослаблять transport fences.
- Touch удержание и browser selection: не перехватывать editable controls, отменять при scroll/movement, проверять настоящий touch route и synthetic click.
- Device detection: проверить iPad desktop UA, Android tablet и Windows touch компьютер, а также explicit preference/reload.
- Размер формы и keyboard viewport: functional scroll/submit при RU/EN, errors и portrait/landscape/малой высоте.

## Migration Plan

Настройки и portable data не мигрируют. Сначала весь пакет исправлений и ранние регрессии; затем согласование версии/inventory и immutable candidate. Применимый Windows/Debian/Web Lab/macOS контур предшествует push/tag/draft, проверке семи assets и publish. Local clients/prototype/Web Lab обновляются только штатными stage-bound wrappers. Production остаётся отдельным этапом.

## Verification scope revision, 2026-10-04

Прямое актуальное указание ограничивает compatibility acceptance проверкой Kaigen: фактической отправкой и получением сообщений. Проверка внутренних данных и собственного поведения qTox не является acceptance продукта. Дополнительные матрицы прямых режимов, proxy/Tor настроек и новая native-pair обвязка исключены из обязательного остатка этого релиза. Уже полученные результаты сохраняются с исходными статусами; неудачные и незапущенные сценарии не превращаются в PASS. Пять продуктовых исправлений, выполненные функциональные проверки четырёх targets, MSI, npm audit, проверенные bundled inputs и семь обязательных release assets остаются в scope. Новые тестовые сценарии и тестовые инструменты не добавляются.
