# Proposal

## Why

Поздний сбой MSI или финализации Windows CI сейчас требует повторять уже успешную компиляцию. Версия релиза повторяется в сценариях, хотя проект уже имеет каноническое значение. Пользователь поручил устранить оба источника лишней работы.

## What Changes

- Отделить успешную сборку Windows от упаковки и финализации зависимым job.
- Передавать только необходимые результаты и доказательства через проверяемый artifact того же Actions run, с привязкой к source SHA, плану проверки и хешам файлов.
- Получать release label из существующего источника версии и проверять согласованность обязательных manifest-файлов.
- Сохранить публичные имена artifacts, обязательные проверки и точные доверенные ограничения исторического publisher.

## Capabilities

### New Capabilities

- `windows-ci-handoff`: повтор упаковки без компиляции с проверяемым внутри Actions обменом результатом сборки.
- `release-version-identity`: единое вычисление версии релиза при проверке согласованности источников и сохранении доверенных publication pins.

### Modified Capabilities

Нет.

## Impact

Workflow Windows, узкие CI/release helpers и их тесты. Не меняются продуктовая версия, приложение, managed components или разрешения публикации. Локально проверяются контракты и негативные случаи; выполнение удалённого Actions требует отдельной точной команды пользователя.
