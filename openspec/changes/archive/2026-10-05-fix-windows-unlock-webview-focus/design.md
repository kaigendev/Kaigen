# Design

## Context

См. proposal.md. Прежняя правка DI33 выполняет нативный WebView `set_focus()` после восстановления окна из трея и сохранена в текущем исходнике. Первый запуск такой операции после загрузки экрана не выполняет. В закреплённых версиях Wry начальный `MoveFocus(PROGRAMMATIC)` вызывается при создании контроллера; Tao не повторяет foreground focus, когда окно уже foreground. Поэтому повторный top-level `set_focus()` не эквивалентен нативному WebView focus.

RootApp считает интерфейс готовым после загрузки состояния профилей, темы и завершения splash. Событие загрузки HTML может произойти раньше. Уже существует IPC `report_webview_heartbeat` с сообщениями при focus/visibility и периодическим heartbeat, а Web-маршрут обрабатывает его как no-op.

## Goals / Non-Goals

**Goals:** восстановить корректное присоединение нативного ввода к готовому Windows WebView без пользовательского minimize/restore; сохранить работоспособность системного индикатора и реального ввода.

**Non-Goals:** изменение языка интерфейса, HKL setters, AttachThreadInput, автоматическое сворачивание окна, изменение профилей либо глобальной настройки Windows.

## Decisions

1. Сначала сравнить реальный синтетический символ, WebView ownership и видимый системный индикатор на текущем артефакте до восстановительного действия. Обычное minimize/restore — отдельный контроль. DOM/HKL сами по себе не доказывают исправление индикатора.
2. Кандидат: передать одно уведомление `startupReady` существующим heartbeat после первого готового маршрута RootApp. На Windows сохранить pending-состояние восстановления и выполнить нативный WebView focus через очередь UI. Page-load отвергнут как слишком ранний; постоянный focus pump отвергнут из-за риска вмешательства во ввод.
3. Перед исполнением подтвердить текущий main WebView, видимость, отсутствие минимизации и foreground HWND. Дубликаты не создают повторных очередей; смена окна отменяет устаревшую задачу. Пока окно неактивно, сохранить pending; следующий штатный focus/visibility heartbeat повторяет допустимую попытку. Ошибка постановки в очередь не означает успеха.
4. Изолировать тестируемую политику однократного восстановления от Windows API. Проверять readiness, повторные сообщения, background startup, скрытие/минимизацию, замену окна и отказ очереди. Включить нативный сценарий первого запуска в сохраняемый тестовый маршрут с disposable profile и проверкой индикатора.
5. Кандидат принимается только после повторения исходного Windows-сценария и контроля отсутствия перехвата фокуса. Если он не исправляет индикатор, сохранить отрицательный результат и уточнить причину до интеграции.

### Уточнение после native baseline

Три запуска того же EXE и WebView2 на WindowsLab (включая холодный Explorer/WinR без CDP) не воспроизвели зависание индикатора. Это не опровергает наблюдение рабочего клиента. Изменение добавляет ограниченное восстановление отсутствующего startup-перехода. Отрицательный контроль RootApp проверяет только отсутствие уведомления готовности; его нельзя выдавать за воспроизведение системного индикатора. Автоматические проверки и наблюдаемые native startup/tray/minimize случаи прошли. После штатной локальной поставки и повторного явно запрошенного restart пользователь подтвердил, что Ctrl+Shift сразу меняет системный индикатор на затронутом рабочем клиенте. Это отдельная host-приёмка; native baseline остаётся NO_REPRODUCTION, а причинный native отрицательный контроль отсутствует. Background/minimized pending timing нативно не выполнялся; он покрыт отдельно восемью deterministic policy-тестами без подмены native timing proof. Точные identities и ограничения — в verification.md.

## Risks / Trade-offs

- [Перехват фокуса после переключения пользователя] → повторная проверка actual HWND/visibility непосредственно на UI thread.
- [Цикл Focused/heartbeat] → состояние queued/completed устанавливается до вызова WebView; один успешный repair на текущий startup.
- [Устаревший callback после rebuild] → привязка к конкретному окну и актуальной generation.
- [Тест скрывает дефект активацией окна] → до начального снимка запрещены Page.bringToFront, minimize/restore и вмешательства в layout/focus; фактическое нажатие поля допустимо как действие пользователя.
- [Тестовый DOM успешен, системный индикатор завис] → отдельные реальные OS screenshots и проверка текста индикатора; не выдавать unit PASS за native proof.

## Migration Plan

Миграция данных не требуется. Собрать локальный кандидат из замороженных inputs; проверить текущий Windows-сценарий; выполнить штатное transaction/program-only обновление рабочего клиента с сохранением защищённых каталогов и отдельный local Web Lab finish. Текущие CI-изменения другого задания сохранить. Публикация не входит в задачу.
