# windows-ci-handoff Specification

## Purpose

Позволить повторять упаковку Windows после успешной сборки, сохраняя доказуемую связь результата с исходниками и выполненными проверками GitHub Actions.

## Requirements

### Requirement: Отдельная повторяемая упаковка
Windows CI SHALL выполнять компиляцию portable-приложения и её проверки в producer job, а MSI, финализацию и публичную выгрузку — в зависимом package job; повтор упавшего package job MUST использовать успешный producer без повторной компиляции portable-приложения. Сборка маленького shutdown helper, необходимого MSI, остаётся частью упаковки.

#### Scenario: Повтор позднего сбоя
- **WHEN** producer успешен, а упаковка упала
- **THEN** повтор использует artifact того же run и source SHA, сохраняя исходную попытку producer и текущую попытку consumer.

### Requirement: Проверяемая передача
Передача MUST связывать точные файлы и доказательства с repository, source SHA, run, producer attempt, планом проверки и хешами. Локальные или чужие artifacts MUST NOT становиться релизным результатом.

#### Scenario: Повреждение или подмена
- **WHEN** хеш, run, исходники, план, набор файлов или путь не соответствует ожидаемому
- **THEN** восстановление и упаковка отклоняются до потребления результата.

### Requirement: Сохранение покрытия и внешнего контракта
Разделение SHALL сохранять обязательные проверки, упаковку PR, публичные имена artifacts и исходные результаты проверок.

#### Scenario: Успешная передача
- **WHEN** корректная передача принята
- **THEN** обычный finalizer проверяет прежние доказательства и готовит прежние публичные artifacts.
