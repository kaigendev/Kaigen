Kaigen для Debian поставляется как единый AppImage x86_64.

1. Распакуйте ZIP в отдельный каталог, доступный текущему пользователю для записи.
2. Разрешите запуск: chmod +x Kaigen-x86_64.AppImage
3. Запустите AppImage из этого каталога.

Kaigen не использует ~/.config, ~/.local/share и другие системные каталоги для
профилей и настроек. Рядом с самим AppImage автоматически создаются каталоги:

  data       общие настройки и служебное состояние;
  profiles   профили, история, черновики, PQ-ключи и очереди;
  downloads  полученные и сохранённые файлы.

Официальный Tor Expert Bundle, включая lyrebird и Conjure, находится внутри
AppImage. Системный Tor не устанавливается и не используется. WebKitGTK и
остальные библиотеки приложения включаются в AppImage при сборке. Исполняемый
type-2 runtime AppImage закреплён immutable release и SHA-256, поэтому упаковщик
не подменяет его автоматически содержимым mutable continuous download.

AppImage launcher выбирает нативный backend Wayland, когда приложение запущено
в полноценной Wayland-сессии, и сохраняет X11 для остальных сред. До загрузки
GTK/WebKit он также включает безопасный fallback для систем, на которых DMA-BUF
даёт пустое окно. Поэтому запускать приложение из терминала с GDK_BACKEND или
WEBKIT_DISABLE_DMABUF_RENDERER=1 не требуется. Любые явно заданные значения
GDK_BACKEND и WEBKIT_DISABLE_DMABUF_RENDERER, включая пустую строку и 0,
сохраняются без изменений.

Runtime AppIndicator включён в AppImage. GNOME Shell не показывает системный
tray без расширения AppIndicator/KStatusNotifierItem: в Debian GNOME установите
и включите пакет gnome-shell-extension-appindicator. Это требование среды
рабочего стола; KDE, Xfce и MATE имеют собственную область индикаторов.

Для переноса закройте Kaigen и скопируйте AppImage вместе с соседними
каталогами data, profiles и downloads. Для обновления замените только AppImage,
не удаляя пользовательские каталоги.

Если в системе отсутствует FUSE 2, AppImage можно запустить командой:

  ./Kaigen-x86_64.AppImage --appimage-extract-and-run

В таком режиме переменная APPIMAGE всё равно указывает на исходный файл, и
portable-данные остаются рядом с ним.
